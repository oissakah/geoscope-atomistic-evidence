# Frozen Phase 2 development refinement protocol

Version 1, 20 October 2026. This is a prospectively specified development run after inspection of the first pilot; it is not a preregistered confirmatory test.

1. Parent ZIP SHA256: `81658b921794ff7d46dee07e1ef71e823605c2b2ef9c6927dc9dd7e6bf6bec66`. All 63 member checksums must pass. The builder regenerates the same 320 case variants from the parent's 40 coordinate-derived measurement records. All 20 source groups remain development data.
2. Models and software reuse exactly the successful parent environment and model manifest. Model files are checked against recorded byte sizes and SHA256 values. Local-only safetensors inference uses BF16, SDPA, greedy decoding, batch size 2, at most 160 new tokens and at most 6,144 input tokens. No truncation, answer repair, automatic retry or model-generated code execution is allowed.
3. Three fixed prompts in `src/phase2/models.py` apply independently to every case: direct, scope checklist and selection only. They receive only the claim and evidence packet/report, with no labels, source-group metadata or previous responses. Native SmolLM extended thinking is disabled and its date is frozen.
4. Direct/checklist schemas are exactly `verdict` and `evidence_ids`. Allowed uppercase verdicts are SUPPORTED, CONTRADICTED and INSUFFICIENT_EVIDENCE. A decisive answer requires exactly one citation; insufficiency requires none. The selector schema contains only `evidence_ids`, with zero or one nonempty, unpadded string.
5. Primary parsing accepts one JSON object or that same object inside one complete enclosing ```json or unlabelled ``` fence. It removes only the fence and surrounding whitespace. No answer extraction from prose, ID correction, case folding, list repair, coercion, duplicate-key acceptance or extra fields is permitted. Bare-JSON compliance is a separate diagnostic. Raw output files are immutable audit evidence.
6. Two selector controls share exactly the same raw model output. The arithmetic control computes from the selected visible record without checking scope. The guard additionally validates pair and physical definition. It returns insufficient evidence after rejecting a known mismatched record and never rescues a wrong selection by searching all records. A nonexistent ID is an error for both controls. No selection is an abstention for both. The fully deterministic scope baseline is reported separately.
7. Report all 320 cases per model/method, retaining missing, malformed, duplicate and failed requests as errors. There are 2,880 generation requests and 15 scored model/method combinations: four methods for each of three models plus three deterministic controls. Selection accuracy is the arithmetic control's joint score; the guard's joint score is a decision outcome, not selection accuracy.
8. Report verdict accuracy, exact citation accuracy, joint accuracy, unsupported acceptance, excess abstention, macro F1, complete threshold-pair correctness, representation-pair correctness and source-group bootstrap intervals. Inspect the tradeoff between acceptance and abstention; do not claim that rejecting every uncertain selection is general scientific understanding. Report raw generation completeness separately from derived answer validity.
9. No holdout has been evaluated. Results guide further development and selection of a final protocol. Before Phase 3, freeze model revisions, prompts, parser, checker, datasets/splits and primary comparisons, using new protected groups. Any later protocol change creates a new development run rather than rewriting previous scores.
